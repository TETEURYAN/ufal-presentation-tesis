# Thesis Defense Presentation (TCC) — UFAL

Defense slides for the undergraduate thesis *"GraphRAG as a multilabel
classifier for liver diseases in electronic health records"*, built on
the **college-beamer** template with UFAL branding. Content is in **English**.

## File structure

```
presentation/
├── pre.tex                # main presentation file (edit here)
├── referencias.bib        # subset of tesis/Ref/SampleReferences.bib used in the slides
├── collegebeamer.sty       # Beamer theme (local copy of college-beamer)
├── src/
│   ├── SZU/                # institution slot actually used for the UFAL branding — see below
│   ├── PolyU/ HIT/ SWU/ SAES/ Red/   # original upstream template institutions (unused)
├── gallery/
│   ├── maceio-background.png   # source street-map image used in the cover (src/SZU/background.png)
│   └── ...                     # other sample images from the original template (unused)
└── README.md
```

Files generated by compiling (`*.aux`, `*.log`, `*.pdf`, `*.bbl`, `*.bcf`,
`*.run.xml`, `texput.*`, etc.) are not source files; `latexmk -C` removes them.

**Important naming quirk:** the UFAL logo/cover assets live under `src/SZU/`
(the theme calls `\usepackage[szu,en]{collegeBeamer}` in `pre.tex`). This is
**not** Shenzhen University — the `szu` institution slot was reused to hold
the UFAL badge logo, the white-map cover background, and the theme's main
color, because that's how the assets were set up manually. If you want to
rename it to a proper `ufal` option later, add a new `\DeclareOption{ufal}{...}`
block in `collegebeamer.sty` mirroring `szu`'s, move the three PNGs to
`src/ufal/`, and update the `\usepackage[...]` line in `pre.tex`.
`src/SZU/` also has a few extra images (`d.png`, `go.png`, `maceio.png`,
`s-logo.png`) that aren't referenced by the theme — likely intermediate
files kept around; safe to ignore or clean up.

## How to compile

Requires `xelatex` + `biber` (for the `biblatex` bibliography) + `latexmk`.

```bash
cd presentation
latexmk pre.tex
```

Clean build from scratch:

```bash
latexmk -C
latexmk pre.tex
```

The engine is pinned to XeLaTeX by `.latexmkrc` (`$pdf_mode = 5;`) and by the
`% !TeX program = xelatex` magic comment on the first line of `pre.tex` — you
no longer need to pass `-xelatex` explicitly. This matters because some
systems set a different default engine system-wide (e.g. this machine's
`/etc/LatexMk` sets `$pdf_mode = 4`, i.e. lualatex); without the project-local
`.latexmkrc`, any tool that invokes plain `latexmk` with no engine flag — like
VimTeX's default config — would silently fall back to that system default
instead of XeLaTeX. A project-local `.latexmkrc` always wins over a
system-wide one, so this keeps the build consistent everywhere.

**If `pre.tex`'s first line ever gets edited by hand:** the magic comment
must be a real comment — `% !TeX program = xelatex`, with the `%`. A version
of this file once had `!TeX program = xelatex` without the `%`, which is not
a comment but invalid LaTeX in the preamble, and broke every compile (not
just VimTeX's) with `! LaTeX Error: Missing \begin{document}`.

`latexmk` automatically runs `biber` and the extra `xelatex` passes whenever
the bibliography changes.

### Why XeLaTeX

`pre.tex` uses `fontspec` (for the `\cascadia` monospace font used in the
author's email on the cover), which requires XeLaTeX or LuaLaTeX — it will
not compile with plain `pdflatex`.

### Font fallback

The cover uses "Cascadia Code" for the author's email line. `fontspec` can
find it either as an OS-installed font or via TeX Live's own `cascadia-code`
font package (this machine has the latter — `fc-list` won't show it, but
`kpsewhich CascadiaCode-Regular.otf` will). `pre.tex` still wraps the font
selection in `\IfFontExistsTF{Cascadia Code}{...}{...}`, falling back to
"DejaVu Sans Mono" on any system where neither is available, so the build
never breaks over a missing font.

### VimTeX / Neovim

Compiles normally via `latexmk` from VimTeX (`:VimtexCompile`). **Known
limitation:** on WSL, forward/inverse search between Neovim and a Linux PDF
viewer (Zathura) depends on a working `xdotool`/X server (WSLg) — if
"jump to source" doesn't work, confirm WSLg is active and `xdotool` is
installed on the Linux side.

## Logo, cover background, and color (`src/SZU/`)

| File               | What it is                                                            |
|---------------------|------------------------------------------------------------------------|
| `color-logo.png`     | UFAL logo mark on a solid blue square (badge, shown top-left on white slides) |
| `trans-logo.png`     | Same mark, white-on-transparent (shown top-left on colored slides — section dividers, references, Q&A) |
| `background.png`     | Cover background: white, with the Maceió street map (from `gallery/maceio-background.png`) positioned on the right |

The theme's main color (`\maincolorRGB`, currently `55, 50, 204`, a
blue/indigo) is set inside `\DeclareOption{szu}{...}` in `collegebeamer.sty`
and matches the solid background used in `color-logo.png`.

**Two real gotchas hit while producing PNGs like these (keep in mind if you
regenerate them):**

1. PNGs must be **8-bit**, not 16-bit RGBA — a 16-bit transparent PNG made
   `xelatex`/`pgf`/`xdvipdfmx` render the logo corrupted (only a fragment of
   the artwork showed up).
2. Solid-color PNGs made with `convert -size WxH xc:'#RRGGBB'` often carry an
   embedded `cHRM` (chromaticity) chunk, which made blue backgrounds render
   shifted toward green in some PDF viewers. Fix: pass `-strip` on the final
   `convert` step to drop color metadata before saving.

If you regenerate any of these assets, export with `-depth 8 -strip`.

The cover (`\maketitle`) uses the theme's default title-page template
(unmodified) with a white background — no custom `\setbeamertemplate{title
page}` override in `pre.tex`. One thing to know: the template always appends
`\\` right after `\insertsubtitle`; if `\subtitle{}` is left undefined (empty),
that trailing `\\` has nothing to end and LaTeX throws `! LaTeX Error:
There's no line here to end.` on `\maketitle`. `pre.tex` works around this
with `\subtitle{\,}` (an invisible thin space) instead of leaving `\subtitle`
unset — same fix applies if `\author{...}` or `\date{...}` ever end with a
stray trailing `\\` right before the closing brace.

## Language

The theme ships `en` and `zh` (Chinese, needs `xeCJK` + XeLaTeX) language
options — no native `pt` option. `pre.tex` uses `\usepackage[szu,en]
{collegeBeamer}`; all theme strings (Table of Contents, References, etc.)
use the theme's built-in English defaults. Only `\qaStr` (the closing Q&A
line) is overridden locally in `pre.tex` via `\renewcommand`, without
touching `collegebeamer.sty`.

## Font size and cover

`pre.tex` uses `\documentclass[9pt]{beamer}` (Beamer's default is 11pt) to
keep the text compact given how dense some slides are. The cover includes
title, (empty/invisible) subtitle, author with email, and date — no separate
advisor slide.

## Bibliography

`referencias.bib` is a copy of a subset of the entries in
`tesis/Ref/SampleReferences.bib` (`tesis/` is read-only and was never
modified). The final References slide uses `biblatex` + `biber` with
`\printbibliography`, numeric style (in-text citations render as `[1]`,
`[2]`, ...).

## Content

`pre.tex` content (Introduction, Relevance, Methodology, Project Status,
Concluding Remarks) is based on `tesis/` (Cap01–Cap04, which is a project
proposal/anteproject rather than a finished thesis — no results/conclusion
chapter exists yet there). Since the defense is final but experiments are
still running, the "Current Status" and "Work in Progress" slides carry
`% TODO` comments marking what to update once real results/conclusions are
ready.
